# Чеклист ручной проверки

Перед началом: `schema.sql` применён, есть 5 аккаунтов (student A, student B, staff, admin, super_admin).
Роли staff/admin/super_admin для теста проще выдать SQL-запросом или через админку.

## Гость (без входа)
- [ ] Любой URL кроме `/login` редиректит на `/login`
- [ ] Неверный пароль → тост «Неверная почта или пароль», а не тишина
- [ ] Регистрация с паролем < 8 символов → понятная ошибка
- [ ] Регистрация нового аккаунта → в списке пользователей он `Ученик`

## Student
- [ ] В меню: «Мои заявки», «Новая заявка», «Профиль». Пункта «Управление» нет
- [ ] `/admin` вручную → редирект на `/`
- [ ] Создать заявку без фото → появляется в списке со статусом «Новая»
- [ ] Создать заявку с фото 1–2 МБ → фото видно на странице заявки
- [ ] Фото > 5 МБ или .gif/.pdf → тост с причиной, заявка не создана
- [ ] Заявка B не видна A; прямая ссылка `/issues/<id заявки B>` → «не найдена или нет доступа»
- [ ] На странице своей заявки статус — просто бейдж, кнопок смены нет
- [ ] Можно написать комментарий к своей заявке; он появляется сразу
- [ ] Профиль: неверный код → тост «Код недействителен…»
- [ ] Профиль: верный код → «Заявка ждёт подтверждения», поле блокируется, роль пока «Ученик»
- [ ] Проверка «руками» (подставьте JWT студента и anon key):
  `curl -X PATCH "$URL/rest/v1/profiles?id=eq.<uid>" -H "apikey: $ANON" -H "Authorization: Bearer $JWT" -H "Content-Type: application/json" -d '{"role":"super_admin"}'`
  → ошибка `permission denied`, роль не изменилась
- [ ] То же для `PATCH /rest/v1/issues` со `status` → 0 строк / ошибка

## Teacher
- [ ] После подтверждения админом: роль в профиле меняется **без перезагрузки** (Realtime)
- [ ] Видит только свои заявки, менять статус не может
- [ ] Блок «Вы учитель или сотрудник?» в профиле пропал

## Staff
- [ ] Заголовок «Все заявки», видны заявки всех, у карточек виден автор
- [ ] Фильтры по статусам показывают верные счётчики
- [ ] На странице заявки есть кнопки статусов; смена → тост, бейдж в списке обновился
- [ ] Комментарий staff помечен плашкой «Техперсонал»; ученик-автор его видит
- [ ] Фото чужой заявки открывается
- [ ] «Управление» в меню нет; `/admin` → редирект
- [ ] Через curl: `POST /rest/v1/rpc/create_invite_code` → «Недостаточно прав»

## Admin
- [ ] Вкладка «Управление» доступна, на заявки выходит бейдж с числом ожидающих
- [ ] Создать код (teacher, 1 использование) → код показан один раз, кнопка «Скопировать» работает
- [ ] После «Скрыть» и перезагрузки показать код повторно нельзя (в таблице только статус и счётчик)
- [ ] Ученик вводит код → у админа **сам** появляется заявка (без F5)
- [ ] Подтвердить → роль пользователя стала «Учитель»; отклонить → осталась «Ученик»
- [ ] Тот же код вторым учеником → «Код недействителен…» (код одноразовый)
- [ ] Просроченный/отключённый код → та же ошибка
- [ ] Пользователи: поиск, смена роли (с подтверждением), отключение/включение
- [ ] Отключённый пользователь при следующем запросе видит «Аккаунт отключён»
- [ ] Для admin недоступны: смена своей роли, роль/отключение другого admin/super_admin, выдача admin
- [ ] Может менять статусы и комментировать любые заявки

## Super_admin
- [ ] Всё как у admin, плюс в списке ролей есть «Администратор» и «Суперадмин»
- [ ] Может назначить admin и снять его; себя изменить/отключить не может

## Ошибки и устойчивость
- [ ] Отключить интернет → любое действие даёт тост «Нет связи с сервером…»
- [ ] Не применён `schema.sql` (нет RPC) → тост «На сервере нет нужной функции…»
- [ ] В консоли нет `Uncaught (in promise)` ни в одном сценарии выше
- [ ] Мобильная ширина (~375px): меню сверху прокручивается, таблицы админки прокручиваются внутри карточки

## Что уже проверено автоматически (в этой сборке)
`tsc --noEmit` и `vite build` проходят. `schema.sql` применён на чистый Postgres 16 дважды подряд (идемпотентность) и прогнан
через 85 SQL-проверок от имени ролей anon/authenticated (RLS, column-GRANT, все RPC, storage-политики, деактивация).
Не проверялось: реальный Supabase (PostgREST, Realtime, Auth), поведение UI в браузере.
